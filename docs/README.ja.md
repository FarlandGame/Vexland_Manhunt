**[Bardiya Alizadeh（Kabir）· Farland_game](https://github.com/FarlandGame) と [Ali · Alivexor](https://github.com/Alivexor) が共同制作した、Minecraftのランナー対ハンターを一通り楽しめるプラグインです。**

Vexland_Manhuntは、試合の準備、チームの役割、追跡の開始、トラッキング、進行状況、報酬、結果表示、管理機能を1つのPaperサーバープラグインにまとめています。ランナーはエンダードラゴンの討伐を目指し、ハンターは最後のランナーを倒そうとします。複数のランナーに対応し、死亡、リスポーン、ディメンション間の移動、再接続があっても追跡を続けられるようにしています。管理者は`/mhgui`のコントロールセンターからメニューで試合を操作でき、プレイヤー向けのメッセージやガイドブックも選択した言語で表示されます。

## Manhuntの体験

- **ランナーとハンターのチーム：** オンラインプレイヤーをどちらかのチームに割り当てます。試合には最低1人のランナーと、1人のハンターまたは役割未割り当てのオンラインプレイヤーが必要です。味方が死亡しても生存中のランナーは続行し、死亡したランナーは、その死亡で試合が終了する場合を除いてハンターになります。
- **演出付きの試合開始：** インベントリとゲームモードを準備し、チームを紹介してから、ルーレットでランナーの先行時間を決めます。そのカウントダウン中、ハンターは動けず、画面のタイトルと音で状況が通知されます。先行時間はランダムで、管理者はハンターを早めに解放することもできます。
- **追跡対象を選べるコンパス：** ハンターには専用コンパスが渡されます。右クリックで対象メニューからランナーを選び、追跡中に対象を変更できます。別のディメンションにいる場合は、直接追跡できるようになるまで関連するポータル経路を案内します。リスポーンしたハンターには追跡用コンパスが再び渡されます。
- **進行状況の表示：** ボスバーと試合情報に、ランナーの装備、ネザーの資源、ブレイズロッド、エンダーパール、エンダーアイ、要塞、ジ・エンドへの進行を反映します。新しいビルドでは、より細かな段階とドラゴンの体力を反映した進行表示が加わります。
- **ランナーのキル報酬：** 試合中にランナーがハンターを倒すと、進行度を考慮した50項目の重み付き報酬プールが使われます。アニメーション付きの抽選、ダブル／トリプル報酬、連続キルの通知、レアアイテム獲得時の演出が含まれます。
- **勝利と結果：** 最後のランナーが死亡するとハンターの勝利、エンダードラゴンを倒すとランナーの勝利です。試合終了のタイトル、祝勝演出、キル／死亡情報、一時的なアイテムの片付けも含まれます。新しいビルドでは、MVP、ダメージ、移動距離の結果も表示します。
- **チーム連絡と便利な機能：** `/teammsg`で味方だけにメッセージを送り、`/trash`で54スロットの廃棄用インベントリを開き、`/nv`で自分の暗視を切り替えられます。
- **メニューによる管理：** コントロールセンターには、役割、開始／リセット、ハンターの早期解放、フレンドリーファイア、サーバーロック、全員のテレポート、回復／食料補充、言語、防護設定、状態、ガイドブックがあります。フリーズと完全リセットは、次の試合の準備にも使えます。
- **多言語ガイド：** ランナー、ハンター、管理者向けの本で、目標、追跡用コンパスの使い方、死亡、準備、コマンドを説明します。1.9.11では、`/mhhelp`でプレイヤーの役割に応じたガイドが渡されます。
- **Paper Anti-Xrayとの連携：** メニューからPaperのワールド単位の保護を設定します。変更を反映するにはサーバーの再起動が必要です。

## 提供された 2.0.0 パッケージで変わったこと

- **1 つに統合された JAR：** Manhunt、変更版 GrimAC 2.3.73、同梱の PacketEvents が 1 つの Bukkit プラグインインスタンスを共有します。このパッケージでは GrimAC や PacketEvents を別途インストールする必要はありません。記述子は `GrimAC` を提供すると宣言しています。アーカイブは平坦化されており、未変更の Grim JAR を内部に格納したものではありません。
- **モジュール状態：** 管理者コマンド `/vexintegration` は Grim の ACTIVE/INACTIVE、Bukkit の所有元、VexAC の状態、PacketEvents の状態、追跡中のプレイヤー数を報告します。ネイティブの `/grim` と `/grimac` コマンドは統合モジュールが登録します。
- **制御された起動：** ローダーには Paper の設定 API と、正確に Minecraft 1.21.11 が必要です。プレイヤーがオンラインの状態での動的ロードと、別個の GrimAC インスタンスを拒否します。統合起動に失敗するとプラグインは無効になり、Grim の保護が無効であることがログに記録されます。サーバー自体は稼働を続ける場合があります。試合を始める前に状態を確認してください。
- **既存データの移行：** 初回の統合ロード時、旧プラグインの両データツリーをバックアップし、統合先が存在しない場合に限って旧 GrimAC データをコピーします。両方が存在する場合は既存の統合データが優先され、結合や上書きは行われません。元のデータは保持されます。
- **移動補正の担当：** `plugins/VexLandManhunt/integration.properties` の既定値は `movement-correction-owner=legacy` です。対応するもう一つの値は `grim` で、それ以外は起動を中止します。grim を選ぶと VexAC の setback／テレポート補正経路が抑制されますが、VexAC のチェック、アラート、証拠記録は残ります。すべての旧式処罰が無効になるわけではありません。
- **ゲームプレイの基盤：** フラットな `/mhgui`、Runner/Hunter のロール循環、VexAC 操作、Smart Hunter Kit V3、一時停止／再開、復旧、683 個の翻訳キーは 1.9.11 に基づきます。これはパッケージ化と統合のリリースであり、観戦機能を備えた 1.13.1 の機能構成ではありません。

## 1.9.11 の基盤から引き継いだゲームプレイ

以下のシステムは 1.9.11 の基盤に追加され、この統合パッケージにも引き継がれています。継承されたゲームプレイ機能であり、2.0.0 の新しい観戦機能ではありません。

| 追加・変更 | 1.9.11での動作 |
| --- | --- |
| **Smart Hunter Kit V3** | リスポーン時の適応型キットが、ランナーの装備、チーム、試合の状況を考慮します。ハンターのキットをランナーの平均装備より弱く保つことを目指す仕組みで、`/mhkit`またはGUIから切り替えられます。 |
| **オーバーワールドの自動スポーン移動** | 対象となるオーバーワールドのランナー付近にワールドスポーンを移します。間隔はオフ、5、10、15、20、30分から選べます。安全な地表の候補を選び、条件に合わない場合は移動しません。 |
| **一時停止と再開** | `/mhpause`でゲームプレイ、試合関連のタイマー、追跡、スポーン移動を停止し、`/mhresume`で続行します。一時停止時間は、試合の実際の進行時間から除かれます。 |
| **再起動／クラッシュからの復元** | 復元レイヤーが、主ファイルとバックアップのスナップショット、定期保存、停止時の保存を使い、試合状態、役割、追跡対象、進行、報酬／死亡タイマー、再接続状態を復元します。 |
| **ランナーの再接続設定** | 以前の固定60分の猶予に代わって、再接続期限を設定できます。新規設定の既定値は15分で、再参加時は10秒間保護されます。サーバー停止時間は数えず、期限切れでランナーがハンターになるか試合が終了する場合があります。 |
| **管理機能の拡張** | 最後のランナーを保護しながら試合中の役割を変更できます。選択したプレイヤーへの操作、チームのテレポート／フリーズ、実行状態の再同期、ショートカットで試合管理を行いやすくします。 |
| **確認付きの設定リセット** | 8秒以内に2回クリックすると、Smart KitがON、自動スポーン移動が15分ごと、再接続猶予が15分になります。新規インストールでは自動スポーン移動はOFFなので、その初期値とは異なります。 |
| **VexAC 3.0** | 移動、戦闘、AutoClick、速度／ノックバック、ワールド内の建築に関するチェックがあります。グループ／全体の切り替え、証拠ログ、管理者への通知、環境やラグへの例外処理も含まれます。 |
| **Ultra Deep Debug v4** | `/mhdebug`で、状態機械、GUI、模擬キット／負荷、翻訳のプレースホルダー、保存から復元までの往復、一貫性の診断を行えます。 |
| **表示の拡張** | より細かな進行情報、ドラゴンの体力表示、MVP／ダメージ／距離の結果、TABでのping情報が加わります。 |
| **コマンドの変更** | `/mhkit`、`/mhspawn`、`/mhpause`、`/mhresume`、`/mhdebug`を追加し、`/mhnone`を削除します。`/mhhelp`はプレイヤー／管理者に応じたガイドになり、`/trash`の別名も追加されます。 |
| **翻訳メッセージの増加** | 各言語の翻訳リソースが446個のメッセージキーから683個に増えています。 |

VexACに含まれるチェックは、Fly、Speed、Timer、Phase、Step、NoSlow、GroundSpoof、Reach、KillAura、AimAssist、wall-hit、BadPackets、AutoClickのタイミングパターン、ノックバックの改変、Scaffold、Tower、FastPlace、Nuker、ブロックへの到達距離を対象とします。UIは「監視のみ」と表示しますが、コンパイル済みコードにはキック処理の経路も含まれています。その表示を頼りにする前に、テストサーバーで実際の対処動作を確認してください。古いビルドには、代わりに従来のAnti AutoClickとAnti Flyの操作があります。

## `/mhgui`での設定と使い方

### 1. 統合ビルドのインストール

1. **Paper 1.21.11 / Java 21** サーバーを完全に停止し、ワールドとプラグインデータをバックアップします。
2. このリリースの `VexLandManhunt-2.0.0.jar` だけを `plugins/` に配置します。旧 Manhunt と単体 GrimAC の JAR は、有効なプラグインディレクトリの外へ移動してください。データフォルダーは保持し、削除しないでください。プレイヤーはこの JAR をクライアントにインストールしません。
3. `/reload` を使わず、通常どおり起動します。統合ローダーが Grim と PacketEvents のライフサイクルを管理します。
4. OP または `vexland.admin` 権限で `/vexintegration` を実行します。`Grim=ACTIVE` と `PacketEvents=true` を確認してから `/mhgui` に進んでください。保護が無効な状態は起動の問題であり、統合インストールの成功ではありません。

Grim の設定は `plugins/VexLandManhunt/grim/` にあり（`config.yml`、`messages.yml`、`punishments.yml`、`discord.yml`）、任意の履歴には `violations.sqlite` を使用します。初回移行のバックアップ先は `plugins/VexLandManhunt-integration-backups/`、完了マーカーは `plugins/VexLandManhunt/integration-migration-v1.txt` です。旧 Grim データと統合先のデータが両方存在する場合、統合先は保持され、警告がログに記録されます。移行処理はシンボリックリンクを拒否します。

`plugins/VexLandManhunt/integration.properties` で移動補正の担当を確認し、他の設定は保持してください。新規導入時の既定値：

```properties
movement-correction-owner=legacy
```

以下の完全な公開メニューガイドは、このパッケージの 1.9.11 ゲームプレイ基盤に沿っています。観戦機能ブランチには専用のアーカイブガイドがあります。

### 2. コントロールセンターを開く

**OP**または**`vexland.admin`**権限を持つ管理者としてサーバーに参加し、次を入力します。

```text
/mhgui
```

以下では、プラグインリリース**2.0.0**の一般向けインターフェースを、英語のボタン名で説明します。実際の表示は選択したサーバー言語に従います。GUI全体を使う場合は、信頼できる**OP**アカウントを使ってください。定義上の権限はコマンドを開くことを許可しますが、付属ビルドの一部のGUI処理では、より厳しいOPチェックがあります。メイン画面は9スロット×5行です。ボタンにカーソルを合わせると、説明と現在の設定を読めます。ほとんどのボタンは通常のクリックで動作します。特殊なマウス操作と確認操作は以下で説明します。小さい1.6.4のメニューは、ガイドの後半に記載しています。

#### 最初の試合を準備する

1. **Player Roles（プレイヤーの役割）**を開きます。参加者の頭アイコンをクリックし、表示される役割を希望のものにしてください。2.0.0では**Runner（ランナー）**と**Hunter（ハンター）**を交互に切り替えます。役割未割り当ての参加者は最初のクリックでランナーになります。左／右／Shiftクリックで別々の役割を直接選ぶ仕組みではありません。必要に応じて**Previous Page（前のページ）**、**Next Page（次のページ）**、**Back to Control Center（コントロールセンターへ戻る）**を使います。
2. 最低1人のランナーと1人のハンターを割り当てます。開始処理で、残った役割未割り当てのオンラインプレイヤーがハンターになる場合があります。全員の役割を明示的に決めておくと、チームが分かりやすくなります。
3. **Friendly Fire（フレンドリーファイア）**をクリックし、味方同士でダメージを与えられるかを選びます。クリック後にON/OFF表示を確認してください。
4. **Language（言語）**でサーバー全体の言語を選びます。この設定は、自分だけでなく全員のメッセージ、インターフェース、通知、ガイドブックに反映されます。
5. **Smart Hunter Kit（ハンターの適応型キット）**、**Auto World Spawn（ワールドスポーンの自動移動）**、**Anti-Cheat（アンチチート）**を確認します。ゲーム内の説明が必要なら、本のボタンから管理者ガイドを受け取ってください。
6. **Server Freeze（サーバーのフリーズ）**がOFFであることを確認し、**Start Match（試合開始）**をクリックします。開始時にはプレイヤーとインベントリを準備し、紹介とランダムな先行時間ルーレットを行ってから追跡を始めます。残しておきたい物は、開始前に参加者のインベントリの外へ移してください。

| 5行目・3列目 | Clear Dropped Items | 自分がいるワールドの落ちているアイテムエンティティを削除します。 |
| 5行目・4列目 | Pause Match / Resume Match | 進行中のゲームプレイと試合タイマーを停止／再開します。 |
| 5行目・5列目 | Emergency Sync | プレイヤーの役割、追跡用コンパス、関連する実行状態を再同期します。 |
| 5行目・6列目 | Reset Settings | 2回クリックの確認後、バランス用の設定を復元します。 |
| 5行目・7列目 | Close | コントロールセンターを閉じます。 |
| 5行目・8列目 | Auto World Spawn | オーバーワールドのスポーン自動移動間隔を選ぶ画面を開きます。 |
| 5行目・9列目 | Manhunt Administrator Guide | 選択した言語の管理者ガイドブックを渡します。 |

装飾用のガラスとタイトル／状態アイテムは、ゲームプレイのボタンではありません。

#### 役割と選択対象

**Player Roles**は、参加者が所属する実際のManhuntチームを変更します。頭アイコンをクリックし、更新後の役割を読んでください。STARTING/RUNNING中もランナー／ハンターの変更は可能ですが、最後のランナーをハンターに変更することは拒否されます。これにより、試合中のランナー側が維持されます。変更後はチームの実行状態と追跡が同期されるため、意図を確認してから役割を変更してください。

**Target Player**は役割とは別の選択です。チームを変えずに、Freeze Target、Clear Target Inventory、Kill Targetなどの操作対象を選びます。希望するオンラインプレイヤーの名前が出るまで切り替えてください。保存済みの対象が利用できなくなると、コードは最初の別のオンラインプレイヤーを対象にする場合があります。対象への操作を行う直前に、必ず名前を確認してください。ほかに誰もオンラインでなければ、対象がないと通知されます。

**Clear Target Inventory**と**Kill Target**は、同じ対象に同じ操作を**5秒以内に2回**クリックする必要があります。1回目は確認待ちにして対象を示し、2回目で実行します。対象を変えたり時間が過ぎたりした場合は、新たな確認が必要です。インベントリの消去は中身を削除します。ランナーを死亡させると、通常の死亡ルールにより試合が終了または変化する場合があります。

**Freeze Team**は、このメニューでチーム別のマウスショートカットを持つ唯一のボタンです。通常の左クリックでランナーチーム、通常の右クリックでハンターチームを選び、Shiftクリックでこの機能が管理する個人／チームのフリーズをすべて解除します。全体のServer Freezeは別の操作なので、プレイヤーがまだ動けない場合は、そのスイッチも別にOFFにしてください。

#### Smart Hunter Kit

**Smart Hunter Kit**をクリックすると、ハンターのリスポーン時の適応型キットをON/OFFに切り替えます。ボタンには現在の状態が表示されます。ONの場合、リスポーンしたハンターは、ランナーの装備と試合状況に応じたキットを受け取れます。付属のプレイヤーガイドでは、そのキットをランナーの平均装備より弱いものと説明しています。OFFの場合、死亡後の自動キットは渡されません。追跡用コンパスは、この設定では無効になりません。

切り替えではなく状態を直接指定するには、`/mhkit on`、`/mhkit off`、`/mhkit status`を使います。静的に確認した、新規設定がない場合の値はONです。

#### Auto World Spawn

**Auto World Spawn**をクリックし、**OFF**、**5 minutes**、**10 minutes**、**15 minutes**、**20 minutes**、**30 minutes**のいずれかを選びます。選ぶと設定を保存して`/mhgui`に戻ります。**Back**は、新しい間隔を選ばずに戻ります。

有効にすると、オーバーワールドにいる活動中のランナー付近で安全な地表を定期的に探し、ワールドスポーンをそこへ移します。オーバーワールドにランナーがいない場合や、安全な候補が見つからない場合は移動しません。新規設定がない場合の値はOFFです。同じ操作をコマンドで行うには、`/mhspawn off`、`/mhspawn 15`、`/mhspawn status`を使います。15の代わりに、対応しているほかの間隔も指定できます。

#### 一時停止、再接続、復元

**Pause Match**は、試合がRUNNINGのときに使えます。ゲームプレイの仕組み、移動／操作、試合タイマー、追跡、スポーン移動を停止します。**Resume Match**でそれらを続行し、停止していた時間を補正します。Server Freezeはプレイヤーを動けなくするだけなので、試合時計を止めたい場合は一時停止の代わりに使わないでください。

ランナーの再接続猶予は変更でき、新規設定がない場合は**15分**です。期限内に再参加するとランナーの状態が復元され、10秒間の再参加保護が付きます。サーバーの停止時間は、保存した猶予を消費しません。期限が切れたランナーはハンターになります。最後のランナーが期限切れになると、ハンターが勝利する場合があります。

**受け取った2.0.0のGUIには、再接続猶予の長さを選ぶ専用画面はありません。** 変更するにはサーバーを停止し、`plugins/VexLandManhunt/config.yml`のほかの設定を残したまま、次の値を編集してください。

```yaml
features:
  custom-reconnect-minutes: 15
```

編集後は再起動してください。1分未満の値は1分に制限されます。**Reset Settings**を使うと、この値は15分に戻ります。コンパイル済みビルドは、サーバーの再起動／クラッシュ後に復元するため、試合／再接続状態とバックアップのスナップショットも保存します。プレイ中にこれらのファイルを手動編集せず、プラグインに管理させてください。

#### Reset SettingsとReset Match

**Reset Settings**は、ボタンを**8秒以内に2回**クリックする必要があります。1回目は確認待ちにし、2回目で**Smart Kit ON**、**Auto Spawn 15分ごと**、**Reconnect 15分**、**ランダムな先行時間**を復元します。新規インストールのAuto World SpawnはOFFなので、その初期値とは異なります。これは設定の変更であり、試合全体のリセットを置き換えるものではありません。

**Reset Match**は既存の試合リセットを行い、一時的な試合状態／アイテムを片付け、次のラウンドのためにプレイヤーをオーバーワールドのスポーンに戻します。このメインボタンには、Reset Settingsの2回クリック確認はありません。**Start Match**では参加者のインベントリを準備／消去する場合があります。クリック前に、どの開始／リセット操作を行いたいのか確認してください。

#### 言語とアンチチートの操作

**Language**でサーバー全体の選択画面を開き、使いたい言語名をクリックします。受け取った両ビルドには、英語、ペルシア語、アラビア語、スペイン語、フランス語、ドイツ語、ロシア語、簡体字中国語、ヒンディー語、ポルトガル語が含まれています。選択はサーバー全体で共有され、保存されます。この日本語READMEによって、プラグインのゲーム内言語選択に日本語が追加されるわけではありません。

**Anti-Cheat**で**VexAC Security**を開きます。内部エンジン全体を切り替えるには**VexAC Master**をクリックし、グループ別に切り替えるには**Movement**、**Combat**、**AutoClick**、**Velocity / AntiKB**、**World / Scaffold**をクリックします。**Anti X-Ray**はPaperの設定済みAnti-Xrayを切り替えるため、変更を反映するにはサーバーを再起動してください。状態、証拠ログ、検出モデルの項目には、現在の仕組みの説明が表示されます。**Back to Control Center**でメインメニューに戻ります。

このビルドのインターフェースは「監視のみ」と説明していますが、静的な検査ではしきい値に基づくキック経路が残っています。メニューの「キックなし」という説明は、実装とドキュメントの不一致として扱い、その動作を頼りにする前に管理下のテストサーバーで確認してください。

#### 統合 GrimAC と旧 VexAC

既存の **VexAC Security** GUI は旧 VexAC エンジンを操作します。Master／グループボタンは新しい Grim 操作パネルではありません。統合 GrimAC はそれと並行して動作します。モジュール状態には `/vexintegration`、Grim 独自のコマンドと権限制御されたツールにはネイティブの `/grim` または `/grimac` を使ってください。Grim の設定と処罰ルールは `plugins/VexLandManhunt/grim/` にあります。

1.13.1 の GrimBridge の monitor／グループメニューと `grim-settings.yml` は、このパッケージの仕様ではありません。VexAC をオフにすれば統合 GrimAC も無効になる、または monitor 表示がキックなしの方針を保証すると考えないでください。Paper Anti-Xray は独立した設定で、変更後は再起動が必要です。

#### ゲーム内ガイドとトラブルシューティング

**Manhunt Administrator Guide**をクリックするか、`/mhhelp`を使うと、選択言語のガイドブックを受け取れます。2.0.0では、プレイヤーも`/mhhelp`で役割に応じたガイドを受け取れます。ハンターはコンパスを右クリックしてランナーを選びます。この追跡画面は、管理者用のTarget Playerとは別です。

役割や追跡が同期していないように見える場合、**Emergency Sync**で関連する実行状態を更新できます。**Match Info**は現在のチームと状態の確認に使えます。試合開始に失敗したら、試合が準備できていること、サーバーフリーズがOFFであること、ランナー／ハンターのチームがあることを確認してください。JARを変更したら、`/reload`ではなくサーバーを完全に再起動します。`/mhdebug`は2.0.0に含まれる管理者用の診断コマンドです。このコマンドがあることは、公開するビルドが実際のサーバーテストに合格したことを意味しません。

#### 以前の1.6.4のコントロールセンター

1.6.4にも、**Player Roles**、**Friendly Fire**、**Start Match**、**Reset Match**、**Release Hunters Now**、**Server Lock**、**Teleport Everyone To Me**、**Heal & Feed Everyone**、**Match Status**、言語選択、**Anti Cheat**、管理者ガイドがあります。役割は**None → Runner → Hunter**の順に切り替わり、試合の開始中／進行中は役割変更がロックされます。

アンチチートメニューには、従来の**Anti AutoClick**（30 CPSのルールと警告／キック処理）、**Anti Fly**、Paperの**Anti X-Ray**があります。ランナーの再接続猶予は**60分**固定です。上記のSmart Hunter Kit V3の切り替え、Auto World Spawnの選択、一時停止／再開、Reset Settingsの確認、拡張された選択対象／ワールド操作は2.0.0の機能で、古いメニューにはありません。

このガイドは、受け取ったJARのメタデータ、付属の翻訳／ヘルプ文、静的逆アセンブルから作成しています。この確認中に、実際のMinecraftサーバーでインターフェースを実行してはいません。

### 3. 追跡をプレイする

ランナーはランダムな先行時間のうちに逃げ、エンダードラゴン討伐に向けて進めます。ハンターは解放を待ち、追跡用コンパスを右クリックしてランナーを選びます。プレイ中は、ディメンションをまたぐ追跡でも対象を変更できます。味方だけと会話するには`/teammsg <message>`、2.0.0で選択言語の役割ガイドを受け取るには`/mhhelp`を使ってください。

ランナーが死亡しても、残りのランナーは続行し、死亡したプレイヤーはハンターになります。ハンターはリスポーンして追跡を続けられます。最後のランナーの死亡や再接続期限切れでハンター側の勝利になる場合があり、エンダードラゴンの討伐でランナー側の勝利になります。

### 4. 一時停止、終了、次の試合の準備

2.0.0では、`/mhpause`で一時停止し、`/mhresume`で続行します。先行時間のカウントダウンが終わる前にハンターを解放したい場合は、`/mhrelease`を使ってください。新しい試合には、コントロールセンターの完全リセットまたは`/mhreset`を使います。リセットは、一時的な試合状態とアイテムを片付け、プレイヤーをオーバーワールドのスポーンに戻します。Paper Anti-Xrayの変更を反映するには再起動が必要です。

## 統合 2.0.0 パッケージの既定設定

静的に確認した、新規設定がない場合の値は次のとおりです。

```yaml
features:
  adaptive-hunter-kit: true
  auto-world-spawn-minutes: 0
  custom-reconnect-minutes: 15
```

`0`は、スポーンの自動移動がOFFであることを表します。GUIの確認付き設定リセットを使うと、代わりに間隔が15分になります。それぞれの設定には、GUIまたは`/mhkit`と`/mhspawn`を使ってください。

## ゲーム内言語とドキュメント

このパッケージは**ゲーム内の 10 言語**を引き継いでいます：英語、ペルシア語、アラビア語、スペイン語、フランス語、ドイツ語、ロシア語、簡体字中国語、ヒンディー語、ポルトガル語です。各同梱翻訳には 1.9.11 と同じ **683 キー**があります。`/mhlang` はサーバー共通の 1 言語を設定し、`language.txt` に保存します。
